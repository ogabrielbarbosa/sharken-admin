# Versão 2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Construir a v2: Leads e Completar no batch, Material com página gerada por agente e vídeo enviado, CRM com WhatsApp (Evolution API), Contrato e Pagamento ligados ao CRM.

**Architecture:** Monorepo pnpm/turbo já existente. Regras puras em `@lps/domain` (sem IO, com testes vitest), acesso ao banco em `@lps/db`, serviços externos em `@lps/integrations`, tarefas pesadas no worker do Mac (`apps/worker`, fila `jobs`), telas e webhooks no Next.js (`apps/web`, server actions). Uma migração nova (`0002_v2.sql`) e outra para a transação de fechamento (`0003_close_deal.sql`).

**Tech Stack:** TypeScript, Next.js 16 (app router, server actions), Supabase (Postgres, Storage, Realtime), vitest + PGlite, Playwright, ffmpeg, Claude Agent SDK, Evolution API, ZapSign, Asaas.

**Spec:** `docs/superpowers/specs/2026-11-11-v2-visao-geral-design.md` e as specs por módulo na mesma pasta (`-leads-`, `-material-`, `-crm-`, `-contrato-`, `-pagamento-`). Telas: `untitled.pen`, frames "v2 · 01" a "v2 · 12".

## Global Constraints

- **LíderHub:** nenhum nome, texto, marca, arquivo ou trecho de código do LíderHub entra no projeto. Não acessar nenhum serviço, banco, API ou MCP do LíderHub. A spec do CRM já resume a lógica a reaproveitar; não abrir o código do LíderHub.
- **Banco local:** nunca rodar `supabase db reset`, `supabase stop --no-backup` ou `supabase stop --all`. Migrações só com `pnpm db:migrate`.
- **WhatsApp:** sem envio em massa, sem envio automático, sem rotação de números. Toda mensagem sai de um clique do Gabriel, um contato por vez. Follow-up agendado só avisa.
- **Textos de tela:** português do Brasil, no tom das telas atuais. Rótulos e valores conforme o `untitled.pen`.
- **Camadas:** `@lps/domain` não faz IO. `@lps/db` recebe `Db` como primeiro parâmetro. Server actions usam `authedDb()` de `@/lib/auth`; webhooks e worker usam o cliente de serviço.
- **Variáveis novas:** `EVOLUTION_URL`, `EVOLUTION_API_KEY`, `EVOLUTION_INSTANCE`, `WHATSAPP_WEBHOOK_SECRET`, `PAGES_HOST`, `PAGE_TTL_HOURS` (padrão 24), `DAILY_FIRST_CONTACT_LIMIT` (padrão 20), `VIDEO_MODE` (`gravado` padrão, ou `ia`), `PAGE_AGENT_MODEL` (padrão `claude-opus-5-5`). As da Evolution e `PAGES_HOST` são opcionais no `getEnv`, exigidas por `requireOptional` no uso.
- **Testes:** `pnpm test` e `pnpm typecheck` verdes ao fim de cada tarefa.
- **Commits:** um por tarefa, com a linha `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **Telefone em formatos diferentes** (com e sem o nono dígito, LID, `@s.whatsapp.net`): mensagens do mesmo número caem no mesmo contato. Teste em Task 4 e Task 13.
2. **Eco do próprio envio chegando antes do `external_id`:** um balão só, sem duplicar. Teste em Task 13.
3. **Status fora de ordem ou webhook repetido** (`lida` antes de `entregue`, mesmo evento duas vezes): status nunca regride e nada duplica. Teste em Task 13.
4. **Envio bloqueado:** contato `nao_contatar`, telefone em `do_not_contact`, segundo follow-up sem resposta ou WhatsApp desconectado: o servidor recusa, mesmo que a tela permita. Teste em Task 3 e Task 14.
5. **Página expirada, removida ou nunca enviada:** quem abre o link vê a mensagem neutra, nunca um erro. Antes do envio, abre por até 7 dias. Teste em Task 8 e Task 10.
